复核日期：2026-10-30。范围为全新演示系统的管理后台、手机 H5、业务接口、奖金计算和数据恢复；依据是用户确认的 V2 方案及原需求表的七张工作表。原表与旧源码只读使用，原附件、原数据库及未脱敏摘录不上传仓库。来源指纹见 [SOURCE-MANIFEST.json](SOURCE-MANIFEST.json)。

## 结论

本轮补齐了配置、会员记录、店铺业务、财务统计和运维入口，并修复权限、订单状态、资金展示及奖金分配边界问题。下表的“归并”表示按 V2 的统一模型承接原功能，页面名称和表结构不照搬旧系统。真实收付款、短信、实时快递轨迹及正式运营环境仍按原定交付边界另行接入。

## 与 V2 方案的重点核对

| 方案要求 | 实现与修正 |
| --- | --- |
| 全部奖金实际计算 | 销售级差、平级、复购固定级差、店补、七星日分红、六级董事和除权、小店、计划1/2、七星复购级差/平级/最高档及八类身份共用纯计算引擎。未给定的五类比例仍是显式演示假设。 |
| 预览与入账一致 | 使用同一业务和规则快照；草稿可比较案例，正式结算不能使用草稿；已发布版本和历史订单不覆盖。 |
| 金额精确与尾差守恒 | 奖池先分配毛奖，再按毛奖分配总管理费，修复极小奖池可能出现个人负管理费的问题；排除负权重；总额保持一致。 |
| 转账保留且可关闭 | 会员间及主小号间共用服务，最低1元、两位小数、免手续费、支付密码、防重、并发与余额约束；公司回收点位可用于明确的公司转账；关闭后接口停止新转账。 |
| 统一账本 | 充值、抵扣、奖励、转换、转账、提现与冲正同事务入账；新增流水顺序号，避免同秒新流水随机排序；日期筛选、余额、账本对账和导出共用口径。 |
| 账户和权限分离 | 多点位登录、本人付款账户校验、部门与本人数据范围、店铺代办范围；发货角色和会员的订单详情不返回全量会员计算快照及其他人的奖金。 |
| 订单状态与撤单 | 详情只读；冻结后禁止激活；同点位禁止重复待激活新人单；会员可取消本人未付款单；退款至店铺受限充值并冲回对应即时奖；保留已日结分红，以后续业绩调整结转。 |
| 合并及分批履约 | 分页及全选跨页，不再只取首屏订单；校验剩余数量、运费变化、渠道与自提类型；未发货申请全部明细撤销后自动关闭。 |
| 手机任务流程 | 统一下单，首页商品入口带正确商品编号；充值与奖励钱包分别可查；提现记录、费用预览、流水来源、店铺转货/充值/发货详情和推荐网络；按点位切换重新加载。 |
| 清理页面文案 | 去掉无关宣传和内部说明；内部奖项代码转为中文业务名称；任务日志不再直接显示内部JSON；系统管理列表去掉无关金额脚注。 |

V8会为既有流水补充稳定的排序号，但不会据此臆造旧记录在同一秒中的真实先后，也不会重算或修改原金额；新入账按真实写入顺序记录。V7、V8、V9均为追加数据库迁移。

## 定时任务映射

原表标题写“共22个”，实际列出第4–20行共17行，其中计划1和计划2合写一行。按独立奖项口径可拆为18项；另外四项没有提供名称与算法。本系统按实际业务合并成以下10个执行任务，不建立无执行逻辑的占位任务。

| 任务 | 承接内容 |
| --- | --- |
| DAILY | 董事分红及除权、七星日分红、日结小店和日结特殊身份；结转撤单的未来业绩扣减。 |
| MONTHLY | 计划1、A店/计划2、月结小店及月结特殊身份。 |
| MONTHLY_REPEAT | 七星复购级差、平级与最高档额外分红。 |
| MEMBERS | 会员、董事、小店及计划资格复核；A店奖励资格与计划2一致。 |
| UPGRADES | 符合实际条件的同步升级审批。 |
| PERFORMANCE | 截至已结束业务日的小市场和团队业绩快照。 |
| RANKING | 会员排名及其18项指标快照。 |
| FINANCE | 每日财务、店铺统计、应收现金快照与汇总。 |
| ARCHIVE | 已完成订单、积分流水和已处理充值的归档；日志按保留策略清理；财务原始记录与晋升历史不物理删除。 |
| RECONCILIATION | 账户余额、借贷平衡及待结转调整的核对。 |

任务使用上海业务日期。日结、每月1日与每月10日的结算周期维持 V2 约定；任务执行和结算批次分别防重，失败记录保留。

## 验证证据与限制

完整结果见 [验收记录](verification/README.md)：96项Java单元及业务集成测试、40项核心接口检查和27项需求扩展接口检查；两端类型检查与生产构建；浏览器操作、20万订单及20万流水的查询/导出，以及独立库恢复。

浏览器检查代表本机 Chromium 中375–430px和桌面页面的表现，未替代真机微信/Safari验收。规模结果代表本机合成数据；正式支付、短信、银行、承运商轨迹、IP属地和生产环境均没有据此宣称完成。真实业务使用前仍需确定五类身份的正式比例及未列出的任务内容，并完成正式通道验收。
