# 初语山言接手检查表

本表用于交接确认。执行写操作的项目放在独立测试库；当前演示库优先查看与只读核对。检查完成后填写实际结果，不能仅按代码存在标记通过。

| 检查项 | 做法 | 应看到的结果 |
| --- | --- | --- |
| 代码来源 | 核对remote、HEAD、status及交接包版本清单。 | GitHub仓库正确，功能基线b057b80可追溯，本地改动已识别。 |
| 启动状态 | `python3 scripts/dev.py status`，打开后台、H5和健康检查。 | 四项服务状态明确，健康检查UP。 |
| 演示登录 | admin、member、shop分别登录。 | 后台与会员身份正确；新账号的首次改密规则有效。 |
| 点位切换 | member在主号与小号间切换。 | 编号、余额、业绩、订单和待激活状态一致切换。 |
| 下单报价 | 查看首购、复购报价和付款账户。 | 首购抵扣最高70%，复购0；本次账户、店铺、商品、应付与月余量可见。 |
| 新人激活 | 独立库创建新人单并付款，由店铺激活。 | 预留资金、点位顺序、资格校验、奖励及账本能互相追溯。 |
| 奖金样例 | 调用`/scenarios`，查1490元销售级差案例。 | 实发268.20、201.15、134.10，合计603.45；此为固定样例关系，不代表任意现场订单。 |
| 转账 | 独立库测试正常转账、错密码、重复请求、余额不足及关闭开关。 | 扣入同事务，失败不变余额，重复不重扣，关闭后无新转账。 |
| 提现 | 独立库申请，再由财务批准或拒绝。 | 冻结、费用、实得、解冻/扣款、审核人和原因一致。 |
| 发货 | 独立库做多单合并、部分数量、自提及撤单。 | 数量不可超占，运费快照正确，历史物流与取消标记保留。 |
| 数据权限 | 以监察、发货及部门角色核对页面与接口。 | 角色不可执行越权操作，订单不泄露全量计算快照。 |
| 规则 | 草稿保存、试算、比较；检查已发布版本。 | 草稿可编辑，已发布只读；同值小数格式不误报差异；不直接改历史版本。 |
| 报表 | 对照订单/奖金明细，导出店铺现金、销量和日报。 | 日期、类型、金额一致；应收现金按已确认本期口径。 |
| 定时任务 | 独立库手工补跑，重试相同账期，制造无效账期。 | 实际执行、失败留痕、不重复入账；真实跨日/月运行继续观察。 |
| 全套回归 | Java测试、两端构建、MySQL API脚本。 | 基线96项Java、40项核心+27项扩展API；新改动补充对应案例。 |
| 备份恢复 | 用新恢复库验证交接SQL。 | SHA256、完整SQL比较及钱包余额核对通过。 |
| 待办认领 | 阅读HANDOVER.md下一步顺序。 | 规则、通道、目标环境、真机与性能工作有明确下一步。 |

交接确认记录建议填写：接手人、日期、实际提交、生效规则、已跑检查、未完成检查和下一项工作。当前未指定接手人，由实际同事填写。
